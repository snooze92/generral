# 10 – User interface

**Principle:** a Sonarr user should feel at home immediately. Same layout, navigation, terminology,
icons, keyboard shortcuts, table/poster/overview views, settings structure, *Show Advanced* toggle,
and light/dark themes. The new parts (Sources, Mapping editor) follow the same visual language.

## Implementation approach

- React + TypeScript SPA built by Vite, served by the backend.
- **Vendor Sonarr's generic UI components** (GPL-3.0, with attribution): `Components/Page/*`
  (header, sidebar, toolbar, content body), `Components/Table/*` (sortable/selectable tables with
  column options), `Components/Form/*` (all inputs, including `ProviderFieldFormGroup` that renders
  `fields[]` schemas), `Components/Modal/*`, `Components/Menu/*`, `Components/Link/*`, `Icon`,
  `Label`, `ProgressBar`, `FilterMenu`/custom filters, `Tooltip`, `Card`, and the CSS variable themes
  (`Styles/Themes/dark.js`, `light.js`).
- **How vendoring works:** `frontend/scripts/vendor-sonarr.mjs` copies the files listed in
  `frontend/scripts/sonarr-files.txt` from a Sonarr checkout pinned in `sonarr-revision.mjs`, and
  applies a short list of mechanical transforms (`window.Sonarr` → `window.Generral`, API root
  `/api/v1`, teal accent, no Sentry, Generral illustrations). Vendored files are never edited by
  hand; CI re-runs the script with `--check`. Files that need real changes (page shell, sidebar,
  header, `FormInput`, settings and status pages) are Generral-owned copies marked
  `Adapted from Sonarr`. Strings are bundled (`src/Strings/en.json`, English from Sonarr's
  `en.json`) instead of fetched from a `/localization` endpoint; other languages are `Later`.
- Data fetching with TanStack Query. SignalR messages invalidate/patch queries (Sonarr's model of
  pushing `episode`, `queue`, `command`, `health` updates).
- Code editor for YAML/templates: CodeMirror 6 with YAML + Scriban highlighting, autocompletion of
  `event.fields.*` from the latest fetched events.

Global header: search box (series + episodes), keyboard shortcuts (`?` for help, `/` for search,
`n` for add new; same as Sonarr), health badge, activity spinner.

## Series index

Same as Sonarr: poster/overview/table views, sort (title, next airing, previous airing, added,
size, …), filters (monitored, continuing/ended, tags, quality profile, custom), and a footer with
counts and disk usage. Each card shows poster, title, episode progress bar (files/monitored),
next airing, and the **source health dot** (green/amber/red).

## Add series

A wizard, since there's no TVDB lookup:

1. **Start:** *From preset* (gallery of shipped + imported presets, searchable, with sport icons)
   or *From scratch*.
2. **Source:** pick an existing source or create one (inline source editor with preview). For
   presets, fields are pre-filled and only parameters show (e.g. TheSportsDB API key, seasons to
   include).
3. **Mapping:** the mapping editor (below), pre-filled from the preset.
4. **Series options** (Sonarr's add-series panel): title, root folder, monitor (`All Episodes`,
   `Future Episodes`, `Missing Episodes`, `Existing Episodes`, `Recent Episodes`, `First Season`,
   `Last Season`, `None`), quality profile, season folders, tags, *Start search for missing
   episodes*, *Start search for cutoff unmet episodes*.
5. **Review:** the episode list preview, then *Add*.

## Series details

Sonarr layout: header (fanart backdrop, poster, title, overview, path, size, quality profile,
monitored toggle, status, tags, **source(s)** with last refresh), toolbar (*Refresh & Scan* →
refresh sources + apply mappings + disk scan, *Search Monitored*, *Preview Rename*, *Manage Episodes*,
*History*, *Edit*, *Delete*, and the new **Mapping** and **Renumber…**).

Season accordions. Each episode row has: monitored toggle, number (`11`, plus a 🔒 icon when locked),
title, part badge (e.g. `Main Card`), air date, status (file quality badge / missing / unaired /
downloading progress), and *Automatic Search* 🔍 / *Interactive Search* 👤 buttons. Orphaned
episodes with files are shown in grey with an "Orphaned" label.

**Episode details modal** (tabs, Sonarr parity + new):
*Details* (overview, air date, file info), *History*, *Search* (interactive search results with
reasons), **Source** (the raw event, all fields, link to the source page, revision history),
**Matching** (the rendered queries and must/mustNot rules; *Test* runs the queries against the
indexers without grabbing and highlights which rule rejected each result).

## Sources

- **List:** name, type, series fed, events count, last refresh/result, next refresh, enabled.
  Actions: *Refresh*, *Edit*, *Delete* (blocked while mappings use it).
- **Editor:** a provider-style form generated from the type's `fields[]` schema, with an
  *Advanced (YAML)* tab, and on the right the live preview described in
  [04](04-sources.md#source-editor-ui).

## Mapping editor

Opened from *Series → Mapping*, or step 3 of Add Series. Split view:

- **Left – rules** with sections that match the YAML (`Filter`, `Variables`, `Parts`, `Season`,
  `Episode`, `Title & metadata`, `Images`, `Search`). Each section has a simple form (dropdowns for
  strategies, a field picker showing all `event.fields` with sample values and ⚠ spoiler badges) and
  a "template" toggle that switches the field to a code editor. *Advanced (YAML)* tab shows the
  whole document.
- **Right – preview** table, described in [05](05-mapping.md#preview--dry-run), with filters
  (*kept only*, *changes only*, *errors only*) and the summary bar.
- **Footer:** *Save* (applies), *Save & Renumber…* (if changes would renumber), *Export preset*,
  *Revert to version…*.

## Calendar

Sonarr parity, using episode `airDateUtc`. Each event block shows the series colour, episode title
and part, and status colour (unaired/downloading/downloaded/missing). iCal feed:
`/feed/v1/calendar/generral.ics?apikey=…` with *unmonitored* / *tags* / *past days* / *future days*
options. Handy for sport, since it gives a personal "what's on" calendar.

## Settings pages

Field names, help texts, defaults and *Show Advanced* gating follow Sonarr. Generral-specific
additions:

| Page | Additions |
|------|-----------|
| Media Management | Generral naming tokens in the token picker; *Metadata approach* hint linking to Metadata. |
| Indexers | *Prowlarr* help box with the exact steps (see [06](06-indexers-and-search.md#prowlarr-integration)); *Use TV search* advanced toggle. |
| Metadata | New consumer **Plex NFO** (enabled by default), alongside *Kodi (XBMC) / Emby* (`Later`). Options: *Series metadata*, *Episode metadata*, *Series images*, *Season images*, *Episode images*. |
| General | *Sources: global request delay*, *Max concurrent source fetches*, *Allow script sources* (read-only, reflects env var). |
| UI | Same as Sonarr (first day of week, date formats, theme, colour-impaired mode) + *Spoiler-free mode* default. |

## Branding

- Name **Generral**, logo: a stylised bracket/ladder suggesting a "general series", accent colour
  different from Sonarr's light blue (e.g. teal `#14b8a6`) so the two apps are easy to tell apart
  side by side.
- Default port **8990** (Sonarr 8989, Radarr 7878, Prowlarr 9696).
- Favicon/PWA manifest; page titles `<Page> - Generral`.
